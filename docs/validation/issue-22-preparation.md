## 你先做的補錄

1. 開啟 DSP，維持目前已核准的解析度、輸入設定與 Starting Save。按 F8 開始，等基準場景自動載入。
2. 用自然速度完成兩個完整回合。第一回合成功後按 F9 重載，第二回合成功後按 F8 結束工作階段，等發布完成並顯示 Ready。
3. 這次特別調整採礦機的完成時機：先供應冶金研究所需材料，再放置並供電給鐵礦採礦機，確認有首次產出，接著處理銅礦採礦機。後續完成熔爐與供料連接。避免較早任務尚未完成時，便提前完成採礦機目標。
4. 告訴我「兩回合已錄好」即可。我會從新 evidence 檢查 task 6／7／11 是否實際啟用、取得正例及有效片段，再安排後續批次。錄製器沒有 active task 的畫面提示，因此上述順序只是針對現有缺口的操作建議，是否有效須由錄後事件核對。

這兩回合是先確認操作順序的試錄，不代表能補足 validation 或 offline-test。第一批固定 hash 屬於 train；後續按已登錄順序使用不同設定，不能靠同一設定反覆 F9 取得不同 split。無須故意等待以拉長時間，也無須自行改 seed。

## 你先做的人工標註

開啟 [本機標註頁](../../runs/issue22-preparation/workbench-delivery/index.html)。可直接用瀏覽器開啟；若需要本機服務，在 repo 執行：

```powershell
.\.venv\Scripts\python.exe tools/serve-annotation-workbench.py runs/issue22-preparation/workbench-delivery
```

接著開啟 `http://127.0.0.1:8823`。

1. 填入判讀者。先試做 10 張重建圖，標出能辨識的游標、配方、物品／數字或建築連接，填入原圖的正確狀態；不能辨識的項目填排除原因。記錄出現的 UI 類型，並在 UI 區域欄填入面板矩形座標。
2. 切到「預測序列分類」，播放前後片段，依未來操作分類為移動／視角、UI、建造／物品或等待。先各找 2 段試做；若候選中找不到某類，在備註填原因並按「無法分類，記錄序列排除」，不要硬改分類。
3. 用第 15 步無損原圖標定關鍵狀態，將受影響區域合併後展開 8 pixel，至少 64×64。頁面提供拖曳框選及展開按鈕；等待組必須使用全畫面。歷史末圖與第 5 步供比對，壓縮影片不作文字／數字判讀依據。
4. 每筆先「加入關鍵項目」，再按「儲存本筆人工確認」。最後按「下載標註草稿」，將 `dsp-annotation-draft.json` 存在 repo 的 `runs/issue22-preparation`，把實際檔名或路徑告訴我。

先核對小批次可避免大量重做。草稿尚未符合正式候選封存格式；我會檢查後再轉換、驗證和執行固定抽樣。補錄使 index 改變時，不能直接把舊草稿當成新輸入的已凍結標籤，必須逐來源原圖核對。最終仍需 200 張重建圖完成標註、quota 滿足，以及四類各 50 段合法序列。
