# 依 #21 十一次連續流程重整微任務安排

分析提出的安排以「電磁學 → 鐵礦採礦機 → 銅礦採礦機 → 冶金供料」作為主要提示順序；後半段保留研究與產線準備並行。原先要求示範者先供應冶金材料以補 active reward 的建議撤回。使用者其後已確認此方案，落地決議見 [排程 v4](../adr/0001-task-schedule-v4.md)。以下保留修訂前的分析及反事實試算，實際轉換結果另行報告。

## 證據與界線

來源為 `runs/live/issue21-five-flows-fixed` 和 `runs/live/issue21-six-flows-batched`。逐一核對 dataset.json 與 transitions.parquet 相對於 COMPLETED 的 checksum，再讀取每回合的節點完成時間、active task、有效性及 reward。逐回合結果與來源 hash 保存於 [機器報告](issue-21-task-order-analysis.json)。

五次與六次各有 5、6 個遊戲成功回合；其中五次的第 3 回合、六次的第 3／6 回合含 unknown_control，故只有 4＋4＝8 個有效完整回合。11 次均可供觀察流程差異，品質 gate 的有效正例不能混入這 3 次無效回合。五次錄製當時掉幀 gate 未過的紀錄也維持原判定。

本分析依錄製事件與轉移表重建完成順序，沒有逐段播放全片，不能由完成時間推定玩家何時開始操作，或判斷哪個建造位置最省路程。科技「排入佇列」、「材料供應完成」與「科技解鎖」是不同事件。

## 實際完成順序

| 比較 | 五次流程 | 六次流程 | 對安排的意義 |
| --- | --- | --- | --- |
| 鐵礦採礦機早於冶金供料完成 | 5/5 | 6/6 | 採礦機不應被冶金供料提示擋住 |
| 銅礦採礦機早於冶金供料完成 | 5/5 | 5/6 | 銅礦優先是合理預設，但不是必要前置條件 |
| 物流供料早於人工熔煉完成 | 3/5 | 5/6 | 兩者有交錯，不應增加彼此的硬依賴 |
| 製造供料早於熔爐連接完成 | 0/5 | 6/6 | 兩批示範採不同順序，都能成功 |
| 線圈產線早於電路板產線完成 | 4/5 | 1/6 | 兩支線沒有固定的唯一正確順序 |

11 次中，鐵礦首次有效產出的中位時間是 58.1 秒，銅礦 112.6 秒，冶金供料完成 132.6 秒，冶金科技解鎖 155.6 秒。時間從各回合開始計算，使用完成事件所屬轉移的結束觀測時間，並非逐幀定位的原始事件時間。

六次流程的第 1 回合是重要例外：鐵礦 53.65 秒、冶金供料 89.85 秒、冶金解鎖 115.82 秒、銅礦 144.16 秒。它說明研究可以在銅礦建置期間推進，因此不能把「兩台採礦機完成」寫成冶金研究的必需條件。

## 建議安排

| 階段 | 主要任務安排 | 可並行或交錯的工作 |
| --- | --- | --- |
| 開局準備 | 開始拆登陸艙，排入五項科技；拆完後安排製造、加入燃料及手挖銅礦 | 拆解／研究／製造背景進度繼續運作；製造、加燃料、採銅不強加彼此依賴 |
| 建立採礦 | 電磁學完成後，優先完成鐵礦採礦機，再完成銅礦採礦機；確認有效供電及實際產出 | 冶金材料可提前準備或供應，提前完成仍保存節點事件 |
| 啟動冶金 | 完成剩餘冶金供料，等待科技解鎖 | 研究耗時屬背景進度，不要求停下其他合法準備 |
| 物流與初期熔煉 | 冶金解鎖後，供應物流研究材料並完成人工熔煉 | 兩者可交錯；不要把物流科技解鎖當成人工熔煉的必要條件 |
| 製造與自動供料 | 物流解鎖後，供應製造研究材料，並完成熔爐供料連接 | 熔爐連接仍需人工熔煉與兩礦採集條件，與製造供料沒有互相依賴 |
| 電磁矩陣準備 | 製造解鎖後，供應電磁矩陣研究，完成線圈與電路板兩支線 | 兩支線可交錯，科技研究在背景推進；建置支線仍須滿足熔爐連接等現有條件 |
| 最終產出 | 兩支線和矩陣科技就緒後，完成研究站自動供料，等待首次產出電磁矩陣 | 研究站設置完成與完整回合成功分開判定 |

這張表表達人可理解的工作安排，不把每一列變成必須全部做完才能進下一列的屏障。提示仍只有一個 active task，背景進度與非 active 完成依原契約保留。

## 最小排程修訂

保留既有 task ID 的語意與 17 維任務條件，將「任務身分」與「排程優先序」分開。第一版只改有一致證據的採礦順序，其他並行組先保留原本的固定優先規則，不因這 11 次資料微調每一對順序。

```text
0, 1, 2, 3, 4, 6, 7, 5, 8, 9, 10, 11, 12, 13, 14, 15
```

16 仍為無可執行任務時的等待狀態。三個電磁學後任務維持相同解鎖條件，不新增 6 → 7 → 5 的硬依賴。保留 active 不搶占、完成後跳過已完成節點，以及非 active 完成只記 reward_vector 的規則。

以原有節點完成時間線逐轉移重播，舊優先序的 active task 與兩份轉移表全部一致，作為分析方法的核對；再只替換優先序作反事實試算。8 個有效完整回合中，且完成轉移有效的正例計數如下：

| 微任務 | 現行 active 正例 | 新優先序試算 |
| --- | ---: | ---: |
| 鐵礦採礦機 | 0 | 8 |
| 銅礦採礦機 | 1 | 8 |
| 冶金供料 | 8 | 7 |
| 其餘微任務 | 不變 | 不變 |

這只證明排程可更貼近現有示範，不代表新的實機試驗，也不是已核准的新訓練標籤。不能把試算計數填回原版 gate，或假設新提示下玩家／模型會保留完全相同的行為。

## 尚須處理的兩個問題

1. 固定優先序無法讓所有並行操作都取得 active 正例。8 個有效回合中，加燃料與手採銅各有 4 個 active 正例，人工熔煉有 5 個、熔爐連接有 4 個、電路板支線有 4 個；這些不能直接解讀為「玩家沒有做」。保留全部節點完成報告，active 正例不足則獨立列出。後續補錄針對已確認的提示安排進行，不要求示範者為了舊排程改掉合理操作。
2. 11 次中有 4 次「矩陣研究供料完成」與「製造科技解鎖」落在同一轉移，當時 active 是等待；其中 2 次屬有效完整回合。task 12 正好由製造解鎖啟用，可能來不及成為 active 就被記為完成。這涉及供料 predicate 的觀測時點及科技佇列的自動消耗，單靠重排優先序無法解決；須核對原始 research_supply／tech_state 時序，再決定供料任務的啟用與完成定義。

目前 #12 明定「ID 同時是優先順序」，所以分開優先序屬正式契約修訂。落地時需版本化原生與離線排程、驗證重播相容性、產生新的衍生資料與 index，並按依賴重建評估輸入。保留原始 evidence、舊標籤與舊版凍結協定，不就地改寫。現在先釐清安排，暫停依舊補錄建議追加資料。
