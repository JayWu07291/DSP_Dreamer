# A 累計 2431 次更新分析與下一輪配方

## 結論

延長訓練有效，完整 200 張圖的 MSE 和 LPIPS 全數改善；但科技樹細節、原圖沒有的 UI、視角偏差仍未解決。四張圖的重播輸出與已保存的重構 PNG 逐像素一致，且移除歷史後，R001、R004、R016 的錯誤仍然存在。這些例子不支持「匯出配對錯位」或「主要只是歷史畫面殘留」的解釋。

下一輪建議從 `final-2000.pt` 再完成 1000 次更新，LR 為 `2e-5 → 1e-5`，換一組抽樣 seed。先不調模型容量、時間 context、遮罩或 loss 權重。末段改善已變慢，應用這一輪的完整 200 圖決定後續追加，而不是先承諾再跑數千步一定會消除錯誤。

log 的 `loss` 是 `MSE / mse_rms + 0.2 × LPIPS / lpips_rms`。分母隨訓練下降，因此原始誤差下降時，正規化總 loss 仍可能上升或停在約 1 附近。不能用這個總 loss 的跨輪數值判定模型變差。以相同的最後 50 步視窗比較，MSE 為 `0.020053 → 0.007664`、LPIPS 為 `0.420708 → 0.257839`，總 loss 卻為 `1.038702 → 1.163288`。

額外訓練最後兩個 250 步視窗，MSE 只再降 3.96%，LPIPS 再降 1.92%，而 LR 已接近 `1e-5`。這表示改善變慢，尚不足斷言已收斂或容量已到極限。latent token 間標準差在兩輪最後 50 步從 0.0275 增至 0.1231，飽和比例從 15.97% 降至 8.43%；與表徵逐漸分化一致，但不能直接換算成 UI 品質。

## UI 與時間差的診斷

重播四張代表圖 R001、R004、R016、R100，使用實際 evaluator 相同的模型、BF16 與原始合法上下文。只讀取所需資料集 metadata 和少量 RGB，沒有全量重做資料核對，也沒有 optimizer 更新或改動訓練帳本。

每張圖比較三種輸入：原有歷史、只保留當前一張、以當前圖重複填滿同樣長度。最後一張 target 始終相同。

四張原歷史輸出的 PNG 最大像素差都是 0，重現了既有輸出。R004 只用當前圖時，原圖沒有的左上面板仍在。R016 的模糊大方框也沒有因移除歷史而消失。這排除了這幾張圖的來源／輸出錯配，並顯示短上下文或歷史殘留不是充分解釋；R100 的歷史仍對重構有影響，不宜據此關閉整個時間模型。

剩餘可能包括罕見畫面的取樣不足、遮罩訓練下學到常見畫面樣式，以及表徵／重構能力不足。這些仍是假說。本次推論沒有改遮罩訓練、抽樣權重或容量，不能判定哪一項是主因，也不宣稱 UI 問題已修復。

另外，兩輪 seed 都是 2202，抽樣公式使用 `seed + 本輪 step`。已核對額外 2000 輪的前 431 步，其 16 個片段的抽樣位置和上一輪逐步完全相同。這不是資料污染，也不表示權重白訓練，但下一輪不必再按相同次序重播；因此改用新 seed。

