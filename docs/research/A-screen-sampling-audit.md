# A 問題畫面的抽樣比例

2026-09-27。針對 `A-20260927-104240-538709` 的 1000 次更新，檢查 train 中的實際畫面與抽樣紀錄，並回查前兩輪。

## 結論

開局畫面確實少，而且以合法片段起點均勻抽樣，會進一步降低回合開頭影格的曝光。這足以支持針對開局片段做抽樣對照，但尚未證明是重構失敗的主因。

科技樹有被持續抽到。一般遊戲畫面中，左上研究 UI 不可見的情況也相當常見。因此不能把所有多出的 UI、科技樹錯誤都解釋成「這類原圖太少」。

共 19 份 train 來源、137,475 張合法模型影格。本輪 16,000 個片段，計入 loss 的影格共 384,000 次，含重複抽樣。

類別會重疊，不能把各列相加。第一列包含 HUD 從螢幕外滑入的過渡畫面，不代表每張都完全沒有 HUD。第二列對應 R001 的開局情況，並包含在最後一列中；第一列涵蓋 R004 所在的開局階段。

本輪實際抽到第一類中的 324/593 張不同影格，約 54.6%；科技樹則為 3025/3531 張，約 85.7%。這是按重建 target 計算的曝光，不表示每次 encoder 都看到完整 UI，訓練仍有隨機 patch 遮罩。

## 為何開局比例會再降低

A 的抽樣器從所有合法 sequence 起點均勻取樣，短片段長 16、長片段長 48。回合中間的一張影格可以包含在多個片段中，但回合最前面的影格只能包含在很少的合法片段中。

依現有所有合法起點直接計算本輪期望曝光，沒有模擬訓練：

| 畫面類型 | 資料本身比例 | 現有抽樣器的期望比例 | 這輪實際比例 |
| --- | ---: | ---: | ---: |
| 開局 HUD 尚未完整出現 | 0.431% | 0.110% | 0.139% |
| 開局 HUD 已出現、研究 UI 不可見 | 0.356% | 0.214% | 0.208% |
| 科技樹 | 2.568% | 2.171% | 2.251% |
| 一般遊戲中研究列不可見 | 13.368% | 12.725% | 12.639% |

第一類的期望曝光僅約資料占比的 25.6%。本輪實際抽得甚至略高於期望，因此這不是新 seed 剛好特別不幸，而是現有片段抽樣方式的結果。不能把 task 均衡當成同義修復，因為同一微任務中仍包含不同 UI 狀態及回合位置。

## 分類方法與限制

分析讀取了全部合法 train 模型影格的 RGB，以固定 UI 區域的邊緣模板相似度分類，再用原圖抽查。沒有修改資料、重新做全量 RGB checksum 核對、執行 GPU 推論或訓練。

- 科技樹看左上頁首。所有陽性相似度為 0.9963–0.9994，其他影格最高 0.1114，分界明顯。四張落在較寬待查區間的影格均檢視過，實際為遊戲畫面。科技樹分布於 19 份來源，task ID 分別有 1、2、16，因此本次沒有拿 task ID 1 代替科技樹標籤。
- `fullscreen_ui` 只輔助過濾。原圖確認它也包含暫停選單，不能直接當科技樹。輸入事件和畫面切換附近可能相差一個渲染影格。
- 開局先限於 task ID 0，再以圖像特徵分辨 HUD 已出現或尚未完整出現。右下 HUD 在後期可能被製造視窗遮住，因此沒有把全資料中的低相似度一律算成開局。另有兩張開局影格未納入這兩類。
- 左上研究列的內容會隨佇列改變，不能只匹配單一圖示。採保守的低相似度區間，另外保留 122 張、277 次曝光的邊界影格，不強行判定。即使把這些邊界全計入，12.639% 也只會增加至 12.711%。

曝光次數是對 log 的精確加總；畫面類型是經視覺抽查的特徵分類估計，不是全資料逐張人工標註，也不是品質 gate 的人工判讀。科技樹目前只分類到頁面層級，尚未區分縮放、平移、懸浮說明、選中節點等細類，不能宣稱 R016 的具體版面已充分覆蓋。

## 下一步的範圍

開局可優先比較「原均勻片段抽樣」與「額外包含回合開頭片段」；從相同 checkpoint 與 seed 出發，固定更新數、loss、mask 和模型，才能分辨抽樣是否有效。只抽 train，不把本次 validation 圖放入訓練。

科技樹和一般無研究列畫面需要分開診斷。現有結果不能支持只靠全體 task 均衡或無限追加原配方，就能消除多出的 UI。科技樹應先看頁面內部版面分布；UI 可見性錯誤則仍需和遮罩、表徵／decoder 的影響區分。本次先完成比例檢查，未修改任何訓練設定。
